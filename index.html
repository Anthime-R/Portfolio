Featured project

VR Suite — LMC2

2025–Now

An in-house VR package built to give the lab a generic, reusable solution rather than one-off builds — configurable editor tooling and a modular runtime, adapted to the needs of different experimental protocols.

  • LabLMC2
  • EngineUnity
  • RoleTools & runtime architecture
  • Year2025–Now
Technical breakdown

Editor Tooling

  • CC4 avatar setup — a custom editor window automates the full avatar workflow: configuring the XR rig, setting up the humanoid rig, and applying VRIK with Full Body (trackers), Hands-Only, or No-Visual embodiment modes, including headset-specific offsets.
  • Calibration — dedicated calibration logic accurately maps the physical player onto the virtual avatar.
  • OpenXR device picker — editor tool to target Meta, Pico or Vive: updates OpenXR settings, enables the required interaction profiles and switches the BuildTarget in one click.
  • Asset bundle pipeline — automates creation, tagging, build and copy of avatar bundles into the final build's StreamingAssets folder.
  • Custom components — a custom inspector for interactable objects, handling grab/release actions.

Runtime Architecture

Modular runtime handling locomotion, interaction and user embodiment for cognitive-science experiments.

  • Dynamic loading — asynchronous avatar instantiation from local or remote AssetBundles via UnityWebRequest and LoadFromFileAsync, rather than hardcoding avatars into the scene — scalable for setups that need to swap characters.
  • Procedural hand animation — independent per-finger flexion driven by user input, with the animation dynamically halted on collision detection (Physics.CheckSphere) on the interaction layer.
  • IK & embodiment — VRIK (FinalIK) integration supporting FullBody (with trackers) and HandsOnly modes, including an artificial delay parameter on body-tracker following for disembodiment-study protocols.
  • Locomotion & comfort — Strategy pattern to swap movement logic (joystick, physical walking, "Wii Sports"-style). Dynamic vignette (tunneling) auto-activates above configurable linear/angular speed thresholds.
  • Interaction system — grabbable-object detection via OverlapSphere by type (Touchable, OneShot, Carryable), coupled to a cross-platform haptic controller generating complex patterns (ramp-up, double-tap).
  • Input assignment — Unity's Input System dynamically binds controllers and Vive trackers (waist, feet) to the CameraRig at initialization.

Project Architecture

  • Assembly separation — runtime and editor code split into separate assemblies, keeping dependencies clean and build times fast.
  • Hardware profiles — ScriptableObjects manage different VR hardware profiles and tracker offsets, so new headsets or trackers can be supported without touching core code.

04

ExpressionCC4

2025–Now

A facial expression and lip-sync toolkit for CC4 avatars — capture and reuse blend-shape expressions, transition smoothly between them at runtime, and auto-rig lip sync from a single editor window.

  • EngineUnity
  • RoleTools & Technical Art (solo)
  • Year2025–Now
Technical breakdown

Expression Capture & Playback

  • Expression capture tool — a custom editor window reads every blend shape weight on a selected renderer and saves them as a reusable expression asset, so expressions can be authored once and reused across avatars.
  • Smooth transitions — expressions blend at runtime by interpolating SetBlendShapeWeight values, with adjustable intensity and duration rather than snapping instantly.
  • Editor-side testing — a custom inspector adds buttons and sliders directly on the component to preview and test transitions without writing test code.
  • Procedural blink system — an independent coroutine drives natural, randomized blinking (interval and duration both randomized) on its own timer, layered on top of any active expression.

Automated Lip-Sync Rigging

  • One-click setup — an editor window auto-configures lip sync on a target CC4 avatar: matches each phoneme to its corresponding viseme blend shape by name (via GetBlendShapeIndex), and creates a dedicated lip-sync controller object with the required components already wired together.
  • Built on uLipSync — integrates the uLipSync package for real-time phoneme detection from audio.
  • Guided setup — the tool prompts the remaining manual steps needed to get lip sync working correctly (assigning voice profiles, adjusting the humanoid rig configuration).
05

Blast

2024

A mobile twin-stick shooter built solo, focused on a scalable architecture: custom object pooling, ScriptableObject-driven data and events, and a procedural mesh generator that builds the arena walls at runtime.

  • EngineUnity
  • RoleSolo dev (code + shaders)
  • Year2024
Technical breakdown

Architecture & Patterns

  • Custom object pooling — a pooling system for the high volume of concurrent projectiles and enemies, avoiding garbage collection spikes, important on mobile.
  • ScriptableObject-driven data — player, enemy and weapon stats live in ScriptableObjects, decoupling balancing data from logic so values can be tuned without touching code.
  • Decoupled event system — a ScriptableObject-based event architecture keeps components loosely coupled rather than wired directly to each other.
  • Procedural mesh generation — a custom builder computes vertices, miter joints, UVs and normals at runtime to build the arena's wall geometry.

Gameplay Systems

  • Modern input handling — Unity's new Input System drives dual-joystick mobile touch controls.
  • Weapon variety — Shotgun, Bouncer (ricocheting bullets), Explosive and a custom SnakeGun, all built on the same flexible weapon system.
  • Enemy AI variety — distinct behaviors (Kamikaze, ShotgunEnemy, Cubsicles, and a multi-part Snake enemy) each demanding a different player strategy.
  • Save data — a persistent progress manager using binary serialization to store level completion and times locally.
06

Hazel

Ongoing

An ongoing 2D physics-based platformer, built with two other members of the Rewind team. Project lead, in charge of planning — twin-stick object manipulation, a vacuum-based inventory system, and multi-phase boss fights.

  • EngineUnity
  • RoleProject lead, planning (team of 3)
  • YearOngoing
Technical breakdown

Core Gameplay & Mechanics

  • Twin-stick physics manipulation — aim, grab and throw physics-based objects via mouse or gamepad right-stick, distinguishing small projectiles from heavy environmental objects.
  • Vacuum combat & inventory — sucks up items, stores them in a visual inventory queue, and fires them back out as physics projectiles.
  • Character controller — coyote time, variable jump heights and wall-climbing, driven by custom AnimationCurves for grounded/aerial acceleration and jump forces, plus environmental interactions (ice friction, timed slow/freeze effects).

Boss AI

  • State-machine boss — a multi-phase boss driven by a randomized state machine (Swoop, Wind, Flash, Feather, Targeted).
  • Varied attack patterns — Flash uses URP 2D lights and line-of-sight raycasts to blind the player, Wind applies continuous physics forces to push them around the arena, and Feather fires a pooled projectile spread via localized rotation.

Architecture & Tooling

  • Procedural tail animation — forward kinematics animate the tail from velocity, distance constraints and AnimationCurves, with an idle return pose.
  • ScriptableObject event system — a decoupled, ScriptableObject-based architecture for modular, scalable communication between systems.
  • Object pooling — handles heavy instantiation of items, boss projectiles and VFX without GC spikes.
  • Modern Unity stack — new Input System, URP 2D lighting, and DOTween for animation and cinematic sequencing.
